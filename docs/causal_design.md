# Causal-дизайн

Главный тезис

«После» ≠ «из-за».

Рост продаж после поста сам по себе не доказывает причинный эффект поста.

Attribution

Attribution отвечает на вопрос:

Кому приписать уже случившуюся продажу?

Он не отвечает на вопрос, была бы продажа без рекламы.

Incrementality

Incrementality отвечает на вопрос:

Какой дополнительный результат возник именно из-за рекламы?

Для причинного вывода нужен дизайн исследования.

Дизайны

## 1. Exploratory pre/post

Для текущей исторической выборки можно сравнивать среднюю дневную выручку до и после события.

Это полезно для диагностики, но не является causal estimate.

## 2. Interrupted Time Series

Полноценный ITS должен моделировать как минимум изменение уровня и/или тренда после вмешательства.

В текущем коде такая модель ещё не реализована.

## 3. Holdout

Для будущих запусков:

выделить контрольную группу;
сохранить остальные условия максимально одинаковыми;
сравнить incremental effect.

## 4. Difference-in-Differences

Сравнить изменение результата в тестовой и контрольной группах до/после воздействия.

## 5. Synthetic Control

Построить контрольную траекторию из похожих каналов / сегментов.

## Что делать в этом кейсе

### Для прошлого

Использовать descriptive pre/post анализ как исследовательский инструмент и не выдавать его за доказанную причинность.

### Для будущего

Проводить holdout-эксперименты и собирать полноценный event/touch log.

## Для ROMI

ROMI_attr — модельная оценка на основании attribution;
ROMI_inc — целевой показатель для бюджетных решений после получения экспериментальных данных.
