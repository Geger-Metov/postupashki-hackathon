# Executive summary

## Проблема

Воронка Поступашек — black box. Бизнес видит оплату и доступ к курсу, 
но не видит рекламные касания, лиды и стоимость размещений. 
Исторический ROMI посчитать нельзя: нет журнала рекламы, нет cost, 
нет связи между Telegram-пользователем и продажей.

Вопрос бизнеса: **какие рекламные активности реально приносят деньги 
и куда направить следующий бюджет?**

## Что знаем / что оцениваем / что пока нельзя узнать

| 🟢 Знаем | 🟡 Оцениваем | 🔴 Пока нельзя узнать |
|----------|--------------|----------------------|
| Заказы, выручка | Attribution | Реальные касания |
| Повторные покупки | ROMI_attr | Cost размещений |
| Пакеты | Прогноз | Incremental-эффект |
| Аномалии | Сопоставление постов | Точная атрибуция |
| Пики выручки | | Связь user → payment |

**Принцип:** не маскировать отсутствие данных моделью.

---

## Решение

MVP: `base.xlsx → orders → posts → classification → match → touches → attribution → ROMI`.

- `load_data.py` — обработка продаж
- `telegram_collector.py` — сбор постов
- `post_classifier.py` — классификация
- `match_posts_revenue.py` — сопоставление
- `attribution.py` — last touch / linear / time decay
- `romi.py` — ROMI calculator
- `pipeline.py` — единая точка запуска

**Запуск:** `python -m src.pipeline`

**Реальное:** base.xlsx, orders, posts.
**Синтетика:** ad_registry, touches — помечены `data_source = synthetic`.

## Архитектура измерения

**Сущности:** user, channel, campaign, placement, creative, post, 
click, bot_start, lead, payment, order, course, revenue.

**Правило:** для каждого события понятно — кто → что → когда → 
откуда → к какой рекламной активности относится.

**User stitching:** tracking link → telegram_user → student_id.

### ROMI_inc

В MVP **не рассчитывается**. Причина: для incremental-эффекта нужен 
holdout или A/B-эксперимент. В исторических данных его нет.

В таблице `romi_by_campaign.csv` колонка `romi_inc = not_available` — 
это осознанное решение, не ошибка.

## MVP

**Что работает:**

- загрузка base.xlsx
- построение orders и daily metrics
- сбор постов из Telegram
- классификация постов (sale / discount / launch / native / content)
- сопоставление постов с пиками выручки

**Что честно помечено:**

- реальные данные: base.xlsx, orders, posts
- синтетика: ad_registry, touches
- оценка: attribution, ROMI_attr
- нельзя посчитать: ROMI_inc

## План внедрения

### Что начать логировать завтра

1. **Tracking links:** campaign / placement / creative
2. **Ad registry:** cost, publication_time, channel
3. **Bot events:** click, bot_start, lead
4. **Диалоги менеджеров:** начало, интерес, источник
5. **Операционный календарь:** запуски, скидки, акции, цены

### Как считать ROMI_inc в будущем

1. Выбрать 2–3 канала для пилота
2. Разделить аудиторию: тест (видит рекламу) / контроль (не видит)
3. Замерить разницу в продажах
4. Посчитать incremental profit
5. ROMI_inc = (Incremental Profit − Cost) / Cost

---

## Ответ на 300 000 ₽

**Не «вот канал», а система принятия решения.**

1. **Пилот:** 2–3 канала с tracking links
2. **Контроль:** holdout-группа
3. **Логирование:** касания, cost, placement
4. **Оценка:** ROMI_attr и ROMI_inc через 2–4 недели
5. **Решение:** перераспределить бюджет в каналы 
   с лучшим incremental ROMI
6. **Цикл:** повторять каждый запуск
