# Assumptions

Один (student_id, timestamp) = один заказ.
Несколько строк с одинаковыми student_id и timestamp объединяются в один заказ, потому что отдельного идентификатора заказа в base.xlsx нет.
Пакет = 2+ курса в одном заказе.
is_bundle = true при items_count >= 2. Это операционное определение, а не доказательство коммерческого типа продукта. Получено 153 пакетных заказа.
amount суммируется по заказу.
Выручка заказа и средний чек рассчитываются по сумме всех строк заказа.
Первый заказ в доступной истории не считается повторным.
Последующие заказы получают is_repeat = true. Получено 22 повторных заказа внутри доступной истории.
История до 4 августа отсутствует.
Нельзя установить, был ли заказ 04.08.2026 первой покупкой человека в принципе.
Исходные суммы не исправляются по предположению.
Подозрительные суммы не удаляются и не заменяются автоматически.
Реальные маркетинговые касания исторически не восстановимы полностью.
В исходных продажах нет полного журнала кликов, переходов, лидов, рекламных размещений и их стоимости.
Синтетические данные явно отделены от фактических продаж.
ad_registry.csv и touches.csv используются для прототипирования и не являются историческими рекламными касаниями покупателей из base.xlsx.
Attribution window = 7 дней.
Это рабочее допущение для будущего attribution engine, которое должно быть проверено на реальных данных.
ROMI на синтетике — модельная оценка.
Реальный исторический ROMI нельзя корректно посчитать без достоверных данных о затратах и связи размещений с покупками.
student_id и Telegram user_id не смешиваются.
Связь между ними появляется только через отдельный stitching / mapping layer.
Pre/post analysis не считается causal ITS.
Простое сравнение средних до/после события используется как exploratory analysis. Для causal inference нужен полноценный ITS, holdout, DiD или другой экспериментальный дизайн.
