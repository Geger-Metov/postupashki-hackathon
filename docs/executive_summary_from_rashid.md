# Executive Summary — Поступашки

## Проблема

Telegram — главный канал продаж, но **маркетинговые касания не логируются**. Видим 795 продаж за 04.08–10.09.2026 (606 покупателей, 18 курсов), но не знаем, какие рекламные активности их принесли. Воронка — black box.

**Бизнес-вопрос:** какие рекламные активности реально приносят деньги и куда направить следующие 300 000 ₽?

## Данные

- **Реальные** (`base.xlsx`): 795 строк продаж, 606 покупателей, 04.08–10.09.2026
- **Синтетические**: registry размещений, касания (click/bot_start/lead) — реальных нет
- **Собранные**: посты из публичного Telegram (точечно)

## Основные выводы

### 🟢 Знаем
- Один заказ = `(student_id, timestamp)`. Пакет = несколько курсов в одном timestamp
- Пик продаж: **08.08–09.08.2026** — вероятно, запуск. Синхронизируем с постами
- Рассрочка: `463.33 × 3`, `237.50 × 2` — влияет на подсчёт заказов
- Топ-курсы: ML старт/про, Алгоритмы старт/про, Аналитика старт/про

### 🟡 Оцениваем
- `ROMI_attr` = (Attributed Revenue − Cost) / Cost — **считаем** по трём моделям attribution
- `ROMI_inc` — через ITS / holdout. **Без эксперимента нельзя утверждать**, что рост после поста = эффект поста
- Классификация постов: sale / discount / launch / native / content

### 🔴 Нельзя узнать
- Реальные costs по размещениям
- Касания до 04.08
- Роль органики и сарафана

## Решение

### 1. Measurement system (для будущего)

```
marketing activity → user touch → lead → payment → revenue
```
Tracking bot ловит `start_param`, связывает с Telegram user_id. При оплате — stitching через `student_id`.

### 2. Attribution (для прошлого)

Три модели: last_touch, linear, time_decay. Окно 7 дней. Результат → `attribution_results.csv`.

### 3. ROMI

- **ROMI_attr** — по attribution
- **ROMI_inc** — ITS / holdout
- Явно разделяем: «что модель приписала» vs «что реклама реально добавила»

### 4. Incrementality (Task 7)

`src/incrementality.py` — Interrupted Time Series. Сравниваем pre/post окна вокруг даты поста.

## MVP

Работающий end-to-end pipeline:

```bash
python -m src.pipeline
```

- `generate_synthetic.py` → ad_registry + touches
- `load_data.py` → orders + order_items + daily_metrics
- `attribution.py` → attribution_results (3 модели)
- `romi.py` → romi_by_campaign + romi_by_placement
- `pipeline.py` — оркестрация

Воспроизводимо из коробки, работает на синтетике + реальных продажах.

## Ответ на «300 000 ₽»

**Система принятия решения, а не один канал:**

1. **Что делать сейчас:** запустить tracking bot на все внешние размещения. Без него следующий бюджет снова утечёт в black box
2. **Что мерить:** `start_param` → `user_id` → `payment`. Мульти-тач attribution + эксперимент (holdout 10% аудитории)
3. **Как сравнивать каналы:** `ROMI_attr` для приоритизации, `ROMI_inc` для финального решения
4. **Как перераспределять:** держим 80% бюджета в топ-3 каналах по `ROMI_attr`, 20% — на эксперименты
5. **Что собрать в первую очередь:** `cost` + `publication_time` для каждого размещения. Без них ROMI не считается вообще

**Одной строкой:** «Без measurement — не тратить. С measurement — распределять по ROMI_inc, а не по интуиции.»

## Ограничения

- Короткая история (5 недель) — не хватает для надёжного прогноза
- Нет реальных cost — используем синтетику, помечаем явно
- Incrementality без эксперимента — только ITS как приближение
- Мы не маскируем отсутствие данных моделью — честно пишем, что нужно начать собирать
